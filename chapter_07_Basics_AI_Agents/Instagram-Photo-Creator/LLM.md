## 0. Prime directive

> **Deliver 4 Instagram photos (9:16, 2160×3840) that are professionally re-contextualized yet provably unchanged in product color, identity, logo, and shape.**

One sentence that governs every design choice:
**LLMs are probabilistic; the product's pixels must not be.** Segment out the product, generate only the *environment*, composite the original product back, then verify numerically.

## 1. Architectural Invariants (non-negotiable)

| # | Invariant | Rationale | Enforcement |
|---|-----------|-----------|-------------|
| **I1** | **The product's RGB pixels are never regenerated by a model.** They are cut out via alpha mask and pasted back. | This is the only way to *guarantee* color/identity preservation, not approximate it. | `composite.py` pastes `product_rgba`; `verify.py` fails if ΔE > 3.0 |
| **I2** | **Model generation is sandboxed to the background region only.** | Keeps the probabilistic step from touching the subject. | Background generated as an empty scene; product supplied only as an alpha matte for shadow/scale reference |
| **I3** | **Every job passes a numeric fidelity gate before export.** ΔE2000 ≤ 3.0 **and** SSIM ≥ 0.95, measured on the product's **opaque core** (alpha ≥ 250) at its exact placement rect. | "Looks fine" is not a gate. | `verify.py` raises `JobFailed` → no output written |
| **I4** | **Canvas is exact: 2160×3840 (9:16). Cover-scale → center-crop. Never stretch.** | Stretching distorts the product = violates the mission. | `enforce_canvas.py` asserts final `size == (2160, 3840)` |
| **I5** | **Product and background are upscaled together, once**, after compositing. | Separate upscaling creates a visible sharp-subject/soft-bg seam. | order fixed in Navigation router |
| **I6** | **Deterministic tooling.** Fixed seeds, pinned deps, no hidden state. Same inputs → same outputs. | Debuggability + reproducibility (BLAST "reliability over speed"). | seed stored in manifest; `requirements.txt` pinned |
| **I7** | **3-layer separation.** `architecture/` (SOPs) ⟶ Navigation (routing) ⟶ `tools/` (atomic Python). Tools never call each other's internals; only the router composes them. | Maximizes reliability; LLM (routing) stays out of pixel math. | code review against this table |
| **I8** | **Secrets only in `.env`.** Never in code, never in `findings.md`, never logged. | Security. | `tools/check_env.py` gate; `.gitignore` includes `.env`, `.tmp/`, `output/` |
| **I9** | **All intermediates in `.tmp/<job_id>/`; only deliverables in `output/<job_id>/`.** | Clean, resumable, no repo pollution. | router enforces; export is the only writer to `output/` |
| **I10** | **Exactly one brand watermark per image** — `@meraki.by.ankita`, small: rendered **text width ≈ 15 % of canvas width** (clamped 3–35 %), faint. No other text overlay ever. | The user owns the brand mark; nothing else may be added. | `watermark.py` draws it; `verify.py` fails if the bbox is missing |

## 2. Layer contracts

```
Layer 0  Web UI (app.py)  Flask. Upload → start job → poll status → preview → download.
                          User-facing surface only. Calls the Navigation router;
                          imports tools. Never does pixel work, never sees the API key.
Layer 1  architecture/    Markdown SOPs. Define GOALS, INPUTS, TOOL LOGIC, EDGE CASES.
                          No code. Golden Rule lives here.
Layer 2  Navigation       Reasoning/routing: ingest → segment → generate → composite
                          → canvas → verify → export. Chooses scene per variant.
                          Does NOT do pixel work.
Layer 3  tools/           Atomic, deterministic, independently testable Python.
                          One responsibility each. Reads/writes JSON + files only.
```

**Dependency rule:** Layer 3 never imports Layer 3 (except a shared `lib/` util with no side effects). Layer 2 wires Layer 3. Layer 0 (web) calls Layer 2. Layer 1 documents all of them.

**Web-layer invariants:**
- **W1** — The API key lives only server-side; never sent to the browser, never in a response body.
- **W2** — `/generate` returns a `job_id` immediately and runs the pipeline on a **background thread** (4 sequential Gemini calls are tens of seconds; blocking the request is forbidden).
- **W3** — The browser polls `GET /status/<job_id>`; job state is a plain dict guarded by a lock.
- **W4** — Uploads are validated (mime ∈ {jpeg,png,webp}, long edge ≥ 1000px, size ≤ 15 MB) **before** any paid API call.
- **W5** — The web layer never mutates images; all pixel work stays in `tools/`.

## 3. Data Schemas (Data-First Rule)

```jsonc
{
  "job_id": "string (uuid4)",              // required
  "source_image": "string (path)",         // required, .jpg/.jpeg/.png/.webp
  "product": {
    "name": "string",                       // e.g. "Amber Glass Serum Bottle"
    "category": "string",                   // bottle | garment | electronics | box | jewelry | other
    "must_preserve": ["color", "logo", "label_text", "shape"]  // default: all
  },
  "variants": 4,                            // int, MUST be 4 for v1
  "aspect_ratio": "9:16",                   // fixed for v1
  "resolution": { "width": 2160, "height": 3840 },  // fixed for v1
  "scenes": [                               // len(scenes) must == variants
    { "id": "marble",     "recipe": "polished Calacatta marble wall + glossy marble floor, raking daylight, floor sheen" },
    { "id": "velvet",     "recipe": "deep emerald velvet drapes in vertical folds, single raking light from the right" },
    { "id": "travertine", "recipe": "bedded travertine wall with an arched niche, stone floor, diagonal window light" },
    { "id": "botanical",  "recipe": "sage lime-plaster wall with leaf dapple, oak plank floor, defocused greenery bokeh" }

```

|------|----------|-------|

| `product_rgba.png` | `segment.py` | RGBA, original RGB + alpha mask |

### 3.4 Web API contract (Layer 0)

| Route | Method | Body / Params | Returns |
|-------|--------|---------------|---------|
| `/` | GET | — | Upload page (HTML) |
| `/generate` | POST | multipart: `image`, `product_name`, `product_category` | `{ "job_id": "uuid" }` (202, immediate) |
| `/status/<job_id>` | GET | — | `{ "state": "queued\|running\|done\|failed", "stage": "segment\|generate\|composite\|canvas\|verify", "progress": 0-100, "outputs": [...], "error": null }` |
| `/result/<job_id>/<n>` | GET | n ∈ 1..4 | JPEG (2160×3840) |
| `/download/<job_id>.zip` | GET | — | ZIP of the 4 finals + `manifest.json` |
| `/recreate/<job_id>` | POST | — | `{ "job_id": "uuid", "seed": n+1 }` (202) — same source, fresh aesthetic set |
| `/settings` | GET | — | Settings page (key **masked** in the HTML) |
| `/settings` | POST | JSON: `llm{…}`, `brand{…}`, `background_provider` | `{ "ok": true, "settings": {…} }` (key masked in the echo) |
| `/settings/test` | POST | JSON: `llm{…}` (optional unsaved key) | `{ ok, model, latency_ms, reply }` or `{ ok:false, error, kind }` (502) |

**Job state machine:** `queued → running(ingest) → running(segment) → running(generate ×4) → running(composite ×4) → running(verify) → running(export) → done | failed`
*(`verify` is the gate: breach → `failed`, no `output/` written.)*

## 4. Behavioral Rules

### The system MUST
- R1 — Cut the product with a real alpha mask and composite the **original** pixels back (I1).
- R2 — Keep the product's **size ratio and orientation** consistent across all 4 shots (a reel reads as one product).
- R3 — Preserve any **label/logo text** legibly (no model redraw of text; it's original pixels anyway).
- R4 — Emit exactly **4** images, each exactly **2160×3840**.
- R5 — Write a `manifest.json` with per-image ΔE/SSIM and the seed used.
- R6 — Fail loudly (`status: "failed"`) rather than ship an image that breaches the gate.
- R7 — Stamp **exactly one** small watermark, `@meraki.by.ankita`, on every image (I10); recreate must
  produce a *new* set (seed+1) while keeping the source's identity byte-faithful.

### The system must NOT ("Do Not" list — user-overridden 2026-09-22)
- D1 — ❌ **Do not** apply color grading / filters / LUTs to the product region.
- D2 — ❌ **Do not** add text overlays, price tags, or slogans. **The single brand watermark of I10 is
  the one allowed mark** (this overrides the earlier blanket "no watermarks" clause — the user asked for it).
- D3 — ❌ **Do not** let props (plants, hands, extra objects) overlap or occlude the product.
- D4 — ❌ **Do not** change product **shape/proportions** (no warping, no stretching).
- D5 — ❌ **Do not** alter reflections that reveal the product's true color — if a reflection must change, keep it color-accurate.
- D6 — ❌ **Do not** silently retry with a different seed and ship a *worse* (identity-drifted) result without flagging it.
- D7 — ❌ **Do not** let the background model touch the product: generation is background-only, always (I2).

## 5. Failure modes & handling

| Failure | Detection | Action |
|---------|-----------|--------|
| Mask empty / product not found | mask area < 0.5% of frame | `JobFailed("MaskEmpty")`; ask user for a cleaner source |
| Halo / color fringe at edges | edge-color variance above threshold | run `pymatting` refine, retry once |
| ΔE > 3.0 after composite | `verify.py` | fail; investigate accidental grade or ICC mismatch |
| Backend returns < 9:16 frame | output size check | regenerate with explicit aspect instruction |
| Upscaler OOM (GPU) | exception | fall back to Lanczos-only, mark `verdict: "pass_with_caveat"` |
| Text/logo unreadable | SSIM on label bbox < 0.98 | fail; re-run segmentation (bad mask, not bad model) |

**Bias:** fail closed. A missing image is better than a wrong-product image.

## 6. Naming & conventions
- Tool files: `snake_case.py`, verb-noun where useful (`enforce_canvas.py`).
- Scene IDs fixed: `marble`, `velvet`, `travertine`, `botanical`. Each scene is a styled **set**
  (wall material + floor material + cove + architecture + directional light), never a flat wash.
- Output naming: `NN_<scene_id>.jpg` (zero-padded so files sort).
- No emojis in code; emojis allowed in `task_plan/progress` docs only.
- JPEG quality 95, `subsampling=0` (4:4:4) — avoid chroma subsampling on the product.

## 9. Live-test deviation & evidence (2026-09-22)

**Probe of the supplied `GEMINI_API_KEY`:**
- Text model `gemini-3.6-flash` → **200 OK** (`CONNECTION_OK`, ~2.2 s).
- Image models `gemini-2.5-flash-image`, `gemini-3.1-flash-image`, `gemini-3.1-flash-lite-image`,
  `gemini-3-pro-image`, `nano-banana-pro-preview` → **429 RESOURCE_EXHAUSTED**, metric
  `generate_content_free_tier_requests`, **limit: 0**.

**Consequence.** Backgrounds are rendered **locally** (ADR-8). The masked-composite chain
(segment → composite → canvas → watermark → verify → export) is unchanged and fully exercised.

**Measured result on `Input/Test.JPG`** (macramé rainbow wall hanging, 1200×1600):
| # | scene | size | ΔE2000 | SSIM | verdict |
|---|-------|------|--------|------|---------|
| 1 | marble | 2160×3840 | 0.057 | 0.9989 | pass |
| 2 | velvet | 2160×3840 | 0.190 | 0.9997 | pass |
| 3 | travertine | 2160×3840 | 0.051 | 0.9991 | pass |
| 4 | botanical | 2160×3840 | 0.059 | 0.9990 | pass |

Segment coverage 21.97 % (rembg `isnet-general-use`). Whole job ≈ **27 s**. Watermark bbox present on
all four. ΔE ≈ 0 is the expected result: the product's own pixels are pasted, so the gate is really
measuring that nothing drifted.

> **Earlier numbers (0.74–0.85 ΔE, 0.980–0.986 SSIM) were measurement artefacts.** `verify` was
> (a) including the feathered edge, where the output is *supposed* to blend with the backdrop, and
> (b) re-deriving the product rectangle from a rounded centre, which landed one pixel off the
> compositor's placement. Fixing both dropped the numbers to the truth: ~0.05 and ~0.999.

## 10. Styled sets, edge de-contamination and grounding (2026-09-22, second pass)

The user rejected flat backdrops: *"It should be aesthetic, with some good luxury setup."* Three
changes followed, all recorded as SOPs before code (Golden Rule):

| # | Change | Why |
|---|--------|-----|
| ADR-10 | **Scenes became layered sets.** `tools/lib/textures.py` adds marble / travertine / velvet / wood / plaster, cove stacking, an arch niche, dapple, blind shadow, bokeh, plus glow and directional light. Each scene stacks wall → cove → floor → architecture → light → vignette → grain. | A gradient is not a room. Sets give depth, material and a light direction the product can sit in. |
| ADR-11 | **Edge de-contamination in `segment.py`.** Semi-transparent fringe pixels take the Gaussian-weighted colour of the nearby opaque product instead of the original backdrop. | The matte keeps the *old* background in its feathered edge; composited onto deep velvet that reads as a bright cut-out halo. |
| ADR-12 | **Grounding in `composite.py`.** Placement is anchored by the product's **base** on the floor; a cast shadow is thrown away from the key light, plus an ambient pool, a contact shadow, an optional floor reflection and an optional back-light bloom. | Without them the product floats. Shadow direction now matches each set's light. |
| ADR-13 | **Gate measured on the opaque core**, at the exact placement rect. | A feathered pixel is meant to blend; measuring it grades the set, not the product. |
